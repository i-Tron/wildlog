# 鸟游 / 流浪小鸟
## 第一版整体设计

**版本**：v0.1
**日期**：2026-10-27
**状态**：可直接进入原型开发
**适用对象**：程序、美术、内容共同执行

> 每天花一分钟，看看一只鸟今天在哪里；认出它、照顾它，等它从旅途中寄回明信片。

## 1. 我们要做什么

这是一款以真实鸟类和自然观察为灵感的治愈型收集游戏。玩家拥有一个小鸟窝，每天会遇到不同的鸟：留鸟可能留下来休息，候鸟会在季节到来时出发，玩家可以查看它经过的城市、收到它寄来的明信片，并逐步点亮鸟类徽章。

游戏借鉴《旅行青蛙》的节奏感，但主题换成鸟类、迁徙和自然观察。它不要求玩家长时间操作，也不把真实鸟类当作可以捕捉或追逐的对象。游戏中的“收集”是认识和记录，不是捕捉野生动物。

第一版只验证一个问题：

> 玩家是否愿意每天打开一次，看看鸟窝和鸟的状态发生了什么变化。

## 2. 第一版的边界

第一版做一个可以交给朋友试玩的 **2.5D 垂直切片**，不是完整商业版本。

### 第一版包含

- 一个鸟窝主场景
- 三种鸟：一只留鸟、一只候鸟、一只冬候鸟
- 今日来访卡
- 鸟类详情卡和简短科普
- 留鸟 / 候鸟两种状态变化
- 一个城市级迁徙时间线
- 一张明信片
- 三枚徽章
- 简单积分和每日状态
- 本地存档
- 2.5D 视觉：2D UI + 低多边形 3D 鸟和场景

### 第一版暂不包含

- 真实 GPS 和实时追踪
- 手机摄像头自动识鸟
- AI 自动生成真实迁徙路线
- AR、开放世界地图和复杂物理
- 社交排行、玩家交易和评论
- 充值、商城和实体徽章订单
- 复杂的鸟叫识别
- 直接投喂野生鸟类的现实任务

这些内容可以作为后续方向，但不能阻塞第一版闭环。

## 3. 玩家体验

### 3.1 第一次打开

玩家进入鸟窝，看到一只小鸟在树枝上。页面告诉玩家今天有一只鸟来访，并提供“认识它”入口。

玩家通过剪影、外形和三条特征认识它，完成后获得一枚未点亮的徽章。点击“邀请它进鸟窝”后，鸟出现在场景中，旁边显示一条简短科普。

### 3.2 第二天打开

- 留鸟：还在鸟窝附近，可以喂一次虚拟食物，心情发生轻微变化。
- 候鸟：可能显示“准备出发”“正在路上”或“已抵达某城市”，玩家可以查看路线时间线。
- 冬候鸟：只在对应季节出现，离开后保留在图鉴中。

玩家收到一张明信片，例如：

> 今天风很大，我在赤峰的草地边遇到了几只同伴。等天气暖一些，我再回来。

明信片内容由已审核的路线节点和模板变量组合而成，首版不让大模型直接决定事实。

### 3.3 每日操作

每天一次的主要操作不超过一分钟：

1. 查看鸟窝变化；
2. 认识今天出现的鸟；
3. 喂食或查看迁徙；
4. 收下明信片或点亮徽章。

玩家可以继续浏览图鉴，但不需要持续在线。

## 4. 页面和场景

### A. 鸟窝首页

核心页面。显示鸟窝、当前鸟、天气或季节装饰、今日状态和入口按钮。

必须能看见：

- 当前有哪些鸟在家；
- 哪只鸟正在路上；
- 今天是否有新来访；
- 是否收到明信片；
- 徽章和积分入口。

### B. 今日来访

一张带剪影或局部形象的卡片。玩家点击后进入识别流程。

识别流程只使用游戏内观察，不要求玩家真的去追鸟。题目可以是：

- 哪个喙形更接近它？
- 它更常见于水边、林地还是城市公园？
- 它现在属于留鸟还是候鸟？

### C. 鸟类详情

包含：中文名、学名、形象、居留类型、常见季节、城市级分布、三条科普和当前状态。

位置只显示城市、区域或生境类型，不显示巢址、夜栖点和精确坐标。

### D. 迁徙时间线

用城市节点和日期区间展示候鸟的旅程：

```text
昆明  →  北京  →  赤峰  →  莫斯科
03/01    04/15    05/05      06/10
```

第一版使用静态演示数据，状态由规则推进，不接实时追踪。

### E. 明信片

一张插画、一句鸟的口吻、一个城市节点和一条科普。明信片可以保存到“旅行相册”。

### F. 徽章墙

按鸟种点亮徽章。第一版每种鸟一枚徽章，后续可以增加地区、季节、连续观察等系列。

## 5. 核心规则

### 留鸟

- 常驻本地或附近区域；
- 每天最多喂食一次；
- 可以连续几天出现在鸟窝；
- 心情和亲密度只做轻微变化；
- 不做复杂养成数值。

### 候鸟

- 按季节进入本地；
- 在鸟窝停留一段时间后出发；
- 出发后显示“路上”或已抵达的城市；
- 玩家可以查看路线和预计回归月份；
- 离开期间仍可收到明信片。

### 积分

积分来自：

- 每日打开；
- 完成一次识别；
- 查看科普；
- 收到或整理明信片；
- 点亮徽章。

第一版积分只做成就反馈，不兑换商品，不与付费绑定。

## 6. 技术方案

### 6.1 客户端

使用 **Cocos Creator 3.8 LTS + TypeScript + 2.5D 混合渲染**。

- 2D：UI、文字、徽章、明信片和少量装饰；
- 3D：小鸟、鸟窝、树、地面、远景和季节装饰；
- 默认正交相机，保持绘本式视角；
- 后续可增加轻微透视、镜头移动、光照和粒子；
- 首发平台：微信小游戏；后续发布 iOS / Android。

Cocos 官方文档提供微信小游戏、iOS、Android、Web 的发布路径，并支持 glTF / FBX 模型导入。[跨平台发布](https://docs.cocos.com/creator/3.8/manual/en/editor/publish/index.html) [微信小游戏发布](https://docs.cocos.com/creator/3.8/manual/en/editor/publish/publish-wechatgame.html) [模型导入](https://docs.cocos.com/creator/3.8/manual/en/asset/model/mesh.html)

### 6.2 数据

第一版使用 JSON + 本地存档，不做账号系统。

建议目录：

```text
bird-game/
  assets/
    birds/
    scenes/
    ui/
    postcards/
  data/
    species.json
    migration-routes.json
    postcards.json
    badges.json
  scenes/
    nest.scene
    encounter.scene
    postcard.scene
  scripts/
    state/
    systems/
    platform/
  docs/
```

运行时状态至少包括：

```json
{
  "day": "2026-10-27",
  "homeBirds": ["sparrow"],
  "travellingBirds": ["swallow"],
  "discoveredSpecies": ["sparrow", "swallow"],
  "postcards": ["swallow_beijing_01"],
  "points": 30
}
```

### 6.3 数据与 AI 的边界

迁徙路线由人工审核的 JSON 数据提供：

```json
{
  "route_id": "swallow_spring_demo",
  "species_id": "swallow",
  "season": "spring",
  "legs": [
    {"city": "昆明", "arrive": "03-01", "depart": "03-10"},
    {"city": "北京", "arrive": "04-15", "depart": "05-01"},
    {"city": "赤峰", "arrive": "05-05", "depart": "05-20"}
  ],
  "status": "demo"
}
```

AI 可以生成：

- 明信片草稿；
- 鸟的口吻；
- 科普文案初稿；
- 不同语气的旅行描述。

AI 不能直接决定：

- 迁徙城市和日期；
- 保护区开放规则；
- 珍稀鸟位置；
- “今天一定能看到”的结论。

## 7. 美术方向与交付规范

### 7.1 视觉关键词

纸张、手绘、安静、轻微不完美、自然观察、低多边形、手绘贴图、柔和阴影。

建议使用低对比米白、苔藓绿、河水蓝、日落橙和泥滩棕。3D 鸟不追求写实羽毛，而是追求轮廓清楚、颜色好认、动作可爱。

### 7.2 工具分工

| 内容 | 工具 | 交付 |
| --- | --- | --- |
| UI、徽章、图标、页面布局 | Figma | 源文件、标注页、PNG |
| 3D 小鸟和场景 | Blender | `.blend` 源文件、`.glb` 运行模型、贴图 |
| 手绘贴图、明信片、2D 装饰 | Procreate / Photoshop / Affinity | 分层源文件、透明 PNG |
| 简单 UI 动效 | Cocos Animation Clip | `.anim` 或场景内动画 |
| 复杂 2D 骨骼 | Spine，第二阶段再引入 | `.json` / `.skel` + `.atlas` + `.png` |

设计源文件必须保留，运行资源另行导出。Cocos 的图集使用 PNG 和 plist，3D 模型优先使用 glTF / GLB。

### 7.3 每种鸟的最小资源包

第一版只先做三种鸟，每种包含：

- 3D 模型一套；
- 待机、进食、睡觉、出发四个状态；
- 一张 2D 识别卡；
- 一张剪影；
- 一枚徽章；
- 一张明信片插图；
- 一页颜色、轮廓、锚点和比例规范；
- `manifest.json`。

示例目录：

```text
bird_swallow/
  source/
    swallow_model.blend
    swallow_texture.psd
    swallow_ui.fig
  runtime/
    bird_swallow.glb
    bird_swallow_albedo.png
    bird_swallow_idle.png
    bird_swallow_badge.png
    bird_swallow_silhouette.png
  preview/
    swallow_contact_sheet.png
  manifest.json
```

### 7.4 资源命名

```text
bird_swallow.glb
bird_swallow_idle.png
bird_swallow_eat.png
bird_swallow_badge.png
bg_nest_spring.glb
ui_badge_frame_gold.png
postcard_swallow_beijing_01.png
```

使用小写英文、下划线和稳定 ID。上线后不随意修改 `species_id`、图片文件名和徽章 ID。

## 8. 双方分工

### 程序侧

- 建立 Cocos 工程和 Git 仓库；
- 创建鸟窝、来访、迁徙、明信片和徽章场景；
- 实现本地存档和每日状态推进；
- 编写 JSON 数据结构和校验；
- 建立 3D 模型导入、材质、动画和换肤流程；
- 打包到微信开发者工具进行测试；
- 负责低端设备性能和触控体验。

### 美术侧

- 确定整体视觉方向和色板；
- 先完成三种鸟的完整资源包；
- 制作鸟窝场景第一套 3D 资产；
- 维护 Figma 设计规范；
- 提供模型、贴图、动画和导出预览；
- 标注锚点、比例、材质和动画状态；
- 确保素材来源和授权清楚。

### 共同完成

- 选择第一批三种鸟；
- 核对鸟类名称、习性和季节信息；
- 审阅迁徙城市和日期；
- 决定每一张明信片的语气；
- 每周用真实手机试玩一次；
- 对“好看、治愈、愿意明天再打开”做人工验收。

## 9. 开发节奏

### 第 1–2 天：冻结方向

程序：创建新的 `bird-game` 工程、初始化 Cocos 版本、建立目录和空场景。

美术：确定 3D / 2D 混合风格，给出一张鸟窝概念图、一只鸟的正侧面和三种主色。

共同：确定三种鸟和它们的留居类型。

### 第 3–7 天：跑通技术链路

程序完成：

- 鸟窝场景；
- 3D 模型导入；
- 点击鸟后的状态切换；
- JSON 读取；
- 本地存档；
- 一张明信片弹窗。

美术完成：

- 一只鸟的 Blender 源文件和 GLB；
- 鸟窝第一套模型；
- 一套 UI 卡片和徽章模板。

### 第 2 周：完成垂直切片

交付一条完整流程：

```text
打开鸟窝 → 今日来访 → 认识鸟 → 鸟进入鸟窝
→ 第二天状态变化 → 查看迁徙 → 收到明信片 → 点亮徽章
```

必须能在手机或微信开发者工具中连续体验三天状态变化。

### 第 3–4 周：扩展到三种鸟

- 接入三种完整鸟资源；
- 补齐三条路线和三张明信片；
- 加入积分流水；
- 做第一次朋友试玩；
- 根据反馈调整点击路径和视觉节奏。

## 10. 第一版验收标准

第一版完成的判断条件：

- 新用户打开后 30 秒内能理解自己有一个鸟窝；
- 第一次体验可以认识并收下一只鸟；
- 留鸟和候鸟的状态明显不同；
- 候鸟离开后能看到城市级迁徙时间线；
- 至少收到一张明信片；
- 至少点亮一枚徽章；
- 关闭并重新打开后状态仍然存在；
- 三种鸟的模型、材质、动画和 UI 资源命名一致；
- 手机小屏上鸟的轮廓和主要颜色清楚；
- 没有精确巢址、夜栖点或诱导追逐野生鸟类的内容；
- 迁徙事实和科普内容均有来源或明确标记为演示数据。

## 11. 今天就可以开始的任务

### 程序

1. 创建独立 `bird-game` Git 仓库；
2. 安装并锁定 Cocos Creator 3.8 LTS；
3. 创建 `nest` 空场景和 TypeScript 项目结构；
4. 写入三种鸟的最小 JSON；
5. 先用占位球体或简单鸟模型跑通点击、状态和本地存档。

### 美术

1. 选定一套低多边形 + 手绘贴图方向；
2. 画出鸟窝第一版概念图；
3. 选择三种鸟；
4. 先完成其中一只鸟的 Blender 模型和四个动作；
5. 建立 Figma 页面、色板、字体和按钮规范。

### 第一个共同检查点

不要先做完整鸟库。第一个检查点只看：

> 一只鸟能否进入一个好看的鸟窝，第二天离开或留下，并寄回一张明信片。

如果这个体验成立，再扩展鸟种、植物、美食和旅游内容。
